# 家庭智能植物管家项目演示演讲稿

## 使用说明

本稿适合约 6 至 8 分钟的现场展示，按照“项目介绍、实物演示、Web 演示、总结”顺序进行。方括号中的内容是演示动作，不需要朗读。

正式演示前应确认：

- 普通 ESP32、ESP32-C5、补光灯、二维舵机云台和水泵已经正常供电。
- 后端与 Web 已启动，普通 ESP32 和 C5 均已连接 Wi-Fi 与云端 EMQX。
- C5 扬声器音量正常，Web 可以显示电脑外接摄像头画面。
- 水枪朝向安全区域，水箱有水，周围电子设备已经做好防水保护。
- Web 页面已经打开，避免在演讲过程中临时输入网址。

## 一、开场与产品定位

各位老师好，我们展示的作品是一套面向家庭阳台、室内种植空间和小型庭院的智能植物养护终端。

家庭种植的困难通常不是不会浇水，而是很难长期、稳定地掌握植物当前的生长环境。例如，家中无人时无法及时查看环境；补光和浇水容易依靠经验；发现植物状态异常后，也不一定能够快速判断原因。

针对这些问题，我们把环境感知、补光、定点灌溉、语音交互、屏幕显示和 Web 远程管理整合到同一套系统中，希望它不只是一个能够联网的花盆，而是一位能够感知、执行、记录和提供建议的家庭智能植物管家。

接下来我将分为两部分进行展示。第一部分展示设备实物和现场交互，第二部分展示 Web 端的远程管理能力。

## 二、实物演示

### 1. 介绍设备组成

[面向实物，依次指出相应模块。]

首先介绍设备的主要组成。

这块普通 ESP32 是现场传感和执行控制器。它负责采集 DHT11 的空气温度与湿度、BH1750 的环境光照以及二氧化碳数据，并通过 Wi-Fi 将真实数据上报到云端 EMQX。

普通 ESP32 还负责控制两个主要执行机构。GPIO14 通过 PWM 控制补光灯亮度；GPIO27 和 GPIO13 分别控制二维云台的水平和垂直舵机，GPIO26 控制水泵。水泵抽取水箱中的水，并输送到云台上的水枪，从而完成指定方向和距离的浇灌。

这块 ESP32-C5 是设备的人机交互终端，主要负责屏幕显示、语音采集、语音播放以及和云端大模型进行交互。它不直接驱动补光灯或水枪，而是把用户的自然语言请求交给后端，后端生成符合统一协议的控制命令，再通过 EMQX 发送给普通 ESP32。

这样的职责划分可以让普通 ESP32 专注于稳定、安全的硬件控制，让 C5 专注于显示和自然语言交互。

### 2. 展示实时环境信息

[指向 C5 屏幕。]

设备上电后，C5 屏幕可以显示当前环境数据和设备状态。这里显示的数据不是预先写入页面的固定内容，而是由普通 ESP32 采集后，经 EMQX 和后端同步到 C5。

用户在植物旁边时，不需要打开电脑或手机，就能直接看到当前空气温度、空气湿度、光照和二氧化碳等信息。

### 3. 展示语音查询

[对 C5 说：“你好小智。”等待唤醒后提问：“现在的空气温度和湿度是多少？”]

现在我通过语音询问当前环境。

[等待 C5 播放回答。]

C5 会采集语音并发送到后端。后端完成语音识别，读取当前真实设备状态，并结合云端大模型生成回答。文字回答产生后，系统同时进行语音合成，再由 C5 扬声器播放。

因此，这里的语音功能并不只是固定关键词控制。用户也可以询问环境是否适合当前植物、数据是否异常，以及日常浇水和补光应注意什么。

### 4. 展示语音开启和调节补光灯

[对 C5 说：“打开补光灯。”]

下面演示通过自然语言控制补光灯。

为了防止语音误识别直接控制真实硬件，系统不会在听到命令后立即执行，而是先复述操作并要求用户确认。

[C5 提示确认后，说：“确认。”观察补光灯开启。]

确认后，后端生成补光灯控制命令，并发布到普通 ESP32 的 MQTT 命令主题。普通 ESP32 收到命令并完成校验后，通过 GPIO14 输出 PWM。当前项目将“打开补光灯”定义为百分之九十亮度，既能明显展示补光效果，也与设备端允许的安全范围保持一致。

[对 C5 说：“把补光灯调到百分之六十。”待提示后说：“确认。”观察亮度变化。]

补光灯不仅支持开和关，也支持百分比亮度调节。例如现在将亮度调整到百分之六十。系统会把用户说出的亮度转换为统一的整数百分比，并保持 C5、后端和普通 ESP32 三端的数值一致。

[如需关闭，对 C5 说：“关闭补光灯。”待提示后说：“确认。”]

关闭命令对应百分之零。设备执行后还会返回命令回执，因此系统能够区分“命令已经发布”和“普通 ESP32 已经实际应用输出”。

### 5. 实物部分小结

以上展示了设备在现场的基本使用方式。家庭用户站在植物旁边时，可以直接查看屏幕，也可以通过语音查询状态、获得养护建议并控制补光灯，不需要理解 GPIO、MQTT 或 JSON 等技术细节。

下面进入 Web 端演示。

## 三、Web 端演示

### 1. 说明家庭项目为什么需要 Web

[切换到 Web 首页。]

有人可能会问：设备已经有屏幕和语音，为什么还需要 Web 端？

这是因为本项目面向家庭使用，而家庭养护具有三个明显特点。

第一，用户不一定一直在植物旁边。上班、上学或外出时，屏幕和现场语音无法提供远程信息，而 Web 可以让用户通过家庭网络中的电脑或其他终端查看设备。

第二，现场屏幕适合快速查看当前状态，但不适合展示长时间历史变化。植物养护通常需要观察几小时甚至几天的趋势，Web 更适合显示曲线、历史记录和执行结果。

第三，家庭设备必须降低误操作风险。Web 可以把摄像头画面、目标位置、设备状态和待确认命令同时展示出来，让用户在控制水枪或补光灯之前看到更完整的信息。

因此，C5 和 Web 不是重复功能。C5 解决的是设备旁边的快速交互，Web 解决的是远程查看、历史分析、精细控制和完整管理。

### 2. 展示首页与真实数据

[展示首页总览和实时监测区域。]

Web 首页集中显示当前空气温度、空气湿度、光照、二氧化碳以及设备在线状态。这些数据来自普通 ESP32 的真实上报，不使用模拟数据。

浏览器不会直接保存 MQTT 账号，也不会直接连接 EMQX。浏览器只与 FastAPI 后端通信，由后端统一完成身份管理、数据存储和 MQTT 收发。这样可以避免把设备账号和密码暴露在网页中，也便于以后扩展更多家庭设备。

### 3. 展示历史记录

[切换到历史数据或趋势页面。]

这里可以查看环境数据随时间的变化。相比只看某一时刻的数值，历史趋势更有实际意义。

例如，用户可以判断室内湿度是否长期偏高、白天自然光是否不足、补光后照度是否发生变化，或者某个异常是偶然波动还是持续问题。对于家庭用户来说，这可以减少完全依靠经验养护带来的不确定性。

### 4. 展示摄像头与定点浇灌

[切换到摄像头和水枪控制区域。]

原型阶段使用的是电脑外接摄像头。Web 端展示真实摄像头画面，并支持在画面中指定需要浇灌的位置。

用户选择目标后，后端根据目标的方向和距离生成水枪控制参数，再通过 EMQX 下发给普通 ESP32。普通 ESP32 先停止水泵，再调整水平和垂直舵机，等待云台稳定后才启动水泵，避免水枪在转动过程中向错误方向喷水。

[在安全情况下选择目标位置，仅展示云台转向；确认周围安全后再执行短时间喷水。]

水平舵机负责左右方向，垂直舵机负责俯仰方向。系统还对舵机角度、喷水时间和水泵输出设置了限制，避免普通舵机超出机械范围，也避免网络中断后水泵持续运行。

在家庭场景中，这项功能的意义是用户不需要一次浇灌整片区域，而是可以针对某一盆植物或某个具体位置进行处理，从而减少用水，也降低水流影响周围家具和电子设备的风险。

### 5. 展示 Web 智能问答和知识功能

[切换到 Web 智能助手或知识库区域。]

Web 端还提供智能问答和植物知识查询。用户可以结合当前环境数据询问养护问题，例如：“当前湿度是否适合番茄？”或者“最近光照偏低应该如何处理？”

系统会结合设备状态、历史数据和植物知识给出建议。涉及补光或喷水等真实硬件操作时，建议和执行是分开的：大模型可以提出操作建议，但必须经过用户确认，后端才会生成正式设备命令。

这种设计保留了智能问答的便利性，同时避免模型回答直接越过安全边界控制硬件。

### 6. 展示 C5 与 Web 的协同

[同时展示 C5 屏幕和 Web 页面中的最新状态。]

C5、Web 和普通 ESP32 使用的是同一套后端状态与设备协议。

通过 C5 调整补光灯后，普通 ESP32 会在后续遥测中上报真实执行状态，Web 页面也会同步更新。反过来，通过 Web 下发控制后，设备执行结果同样可以进入后端记录，并在其他终端查看。

这意味着家庭成员可以使用不同的交互方式，但看到的是同一台设备的真实状态，不会形成彼此独立、互相矛盾的控制系统。

## 四、总结

[回到实物与 Web 同时可见的位置。]

我们的项目围绕家庭植物养护建立了一条完整的真实链路：

普通 ESP32 负责环境感知和硬件执行；ESP32-C5 负责现场屏幕与语音交互；FastAPI 后端负责数据、命令、安全确认和设备协同；云端 EMQX 负责可靠消息传输；Web 端负责远程查看、历史分析、摄像头定位和精细管理。

对于家庭用户来说，实物终端让日常操作足够直接，Web 端则突破了时间和空间限制，让用户能够远程了解植物状态、追踪历史变化并更谨慎地控制真实设备。

本项目最终希望实现的不是单一的自动浇水功能，而是一套集环境监测、精准执行、可视化展示、远程管理、语音问答和智能决策于一体的家庭智能植物管家。

我的演示到这里结束，谢谢各位老师。

## 五、现场异常时的备用话术

### 1. C5 没有识别到语音

当前环境噪声可能影响了语音识别，我重新唤醒设备并靠近麦克风演示。系统的控制仍然要求二次确认，因此一次识别失败不会直接造成硬件误动作。

### 2. Web 暂时没有刷新数据

页面展示的是普通 ESP32 的真实上报，而不是本地模拟数据。当前没有新数据时，系统会保留不可用或离线状态，不会使用随机数伪装设备正常。

### 3. 水枪不适合现场喷水

考虑到现场电子设备和人员安全，这里只展示二维云台对目标位置的转动。水泵控制使用相同的正式命令链路，并具有定时停止和网络异常停泵保护。

### 4. 摄像头暂时不可用

原型阶段使用电脑外接摄像头。如果摄像头被其他程序占用，Web 会明确显示连接异常，而不会使用预录画面替代真实画面。摄像头恢复后，页面可以继续使用真实视频流。

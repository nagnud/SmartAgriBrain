# 前端业务逻辑

最后同步日期：2026-07-22。

## 1. 前端职责

前端是面向温室管理人员的 Vue 3 单页应用，入口为 `src/main.ts`，根组件为 `src/App.vue`。浏览器只访问 FastAPI 的 REST、SSE、WebSocket 和静态资源接口，不直接连接 MQTT，也不保存设备 MQTT 账号。

前端负责四类工作：

- 展示站点遥测、设备在线状态、历史趋势、天气、报警和视觉分析结果。
- 把用户的手动控制、水枪目标和助手确认操作提交给 FastAPI。
- 运行页面侧智能托管计算、交互状态和本地降级逻辑。
- 维护浏览器界面状态，并通过后端应用状态接口同步到其他浏览器会话。

设备是否真正执行必须以后端命令状态和设备 ACK 为准，页面提交成功不等于物理动作成功。

## 2. 启动与生命周期

### 2.1 页面挂载

`src/main.ts` 创建 Vue 应用、加载全局样式并挂载 `App.vue`。`App.vue` 挂载后按以下顺序工作：

1. 初始化助手对话线程。
2. 恢复浏览器与后端保存的仪表盘状态。
3. 加载最新遥测、站点快照、报警、设备健康、天气和历史数据。
4. 加载摄像头定位参数、知识库和在线农业数据源。
5. 建立站点 SSE 连接并读取 C5/Web 共享助手会话。
6. 加载当前作物位置和水枪状态。
7. 启动定时刷新和页面事件监听。

### 2.2 定时任务

- 每 500 ms 更新水枪倒计时显示，不向设备发送命令。
- 每 5 s 通过 REST 校准仪表盘状态，作为 SSE 之外的恢复手段。
- 每 60 s 拉取最多 12 小时站点历史并合并到现有曲线。
- 动态水枪会话单独维护 heartbeat；离开动态模式或组件卸载时停止。
- AI 分析只在相关视图可见且页面处于前台时按间隔调度，避免重复请求。

组件卸载时会关闭 SSE、计时器、语音识别、拖动监听并释放浏览器 Blob URL。

## 3. 页面模块

### 3.1 首页总览

首页聚合站点状态、核心环境指标、天气、趋势图和摄像头生长分析。摄像头模块可以读取后端摄像头流、抓帧、识别当前作物位置并显示定位结果。页面可以保存相机内参、畸变参数、安装高度和后端采集配置。

### 3.2 设备控制

设备控制包含普通执行器、智能托管和二维水枪控制。

普通执行器通过站点命令接口提交百分比目标。当前统一设备契约只允许普通 ESP32 执行 `pump`、`grow_light`、`pan`、`tilt` 和水枪 `target_position`；页面中仍存在的风机、加热、降温、通风和 CO2 控制属于旧界面兼容逻辑，不能据此认定现场硬件已经支持。是否隐藏这些入口等待 [Q-025](../../docs/open-questions.md) 确认。

智能托管在 `src/services/smartControl.ts` 中根据传感器当前值、最近趋势、目标区间和天气计算 0 到 100 的需求值。每轮变化通常限制为 15，紧急条件下限制为 35，以减少控制突变。水泵目前由水枪功能独占，`waterPumpSmartControlPaused=true` 会强制托管水泵需求为 0。

水枪支持静态和动态两种模式：

- 静态模式提交一次目标坐标、喷射开关、连续或定时策略。
- 动态模式先创建会话，再按递增序号更新目标，并用 heartbeat 维持会话。
- 喷射启停与目标更新是不同请求；停止动态模式时后端负责进入安全状态。
- 页面展示的是后端水枪状态，真实动作仍依赖 MQTT 和 ESP32 ACK。

### 3.3 实时监测

实时页展示温度、光照、CO2、土壤湿度等指标及目标范围。点击指标可打开编辑器，修改后的报警范围会保存到后端并持久化页面状态。SSE 遥测到达时会立即更新卡片，同时把数据合并到历史缓存。

### 3.4 历史曲线

历史页从站点历史接口读取真实记录，按时间窗口压缩为图表点。页面支持 5 分钟到 12 小时窗口和多指标选择。相同时间槽保留较新的记录，定时 REST 校准用于补回 SSE 断线期间的数据。

### 3.5 病害识别

病害页接收上传、拖放或剪贴板图片，通过视觉接口分析病害，并显示风险、建议和知识来源。原图与分析结果可以保存到病害图片库；删除操作会同时更新页面列表。摄像头生长分析与病害图片库共用部分视觉类型，但调用流程相互独立。

### 3.6 AI 农事建议

AI 建议把当前遥测、天气、历史趋势、病害结果和摄像头结果组合后提交给后端。后端可以结合本地知识库与在线农业来源返回风险等级、建议和引用。页面自动请求只在视图可见时运行，手动刷新使用强制检索模式。

### 3.7 知识库管理

知识库页支持知识库和条目的新增、修改、删除、查询分析，以及在线农业来源的启停和连通性测试。删除和覆盖修改前会要求用户确认。知识库实体保存在后端数据库，不保存在前端源码中。

### 3.8 报警记录

报警页读取设备报警记录、设备健康状态和报警阈值。用户确认报警后，页面重新同步记录。报警确认只表示人员已处理该提示，不代表异常物理条件已经恢复。

## 4. 数据通信

### 4.1 API 客户端

所有浏览器请求集中在 `src/services/api.ts`。基础地址来自 `VITE_API_BASE_URL`，默认是 `http://localhost:8000`；站点 ID 来自 `VITE_SITE_ID`，默认是 `greenhouse_001`。

`requestJson` 统一处理 JSON 请求、可选超时、HTTP 错误和用户可读错误。图片上传、流式响应和摄像头资源因协议不同使用单独请求函数，但仍复用同一基础地址。

### 4.2 站点状态与 SSE

页面优先使用 `/api/v1/sites/{site_id}` 站点接口。站点 SSE 处理以下事件：

- `telemetry`：刷新站点快照并合并历史点。
- `device_status` 和 `capabilities`：刷新设备在线状态与能力。
- `command_update`：更新命令生命周期和助手动作状态。
- `water_gun`：同步水枪会话、目标和喷射状态。
- `smart_control`：同步托管开关、参数模式和最后发布时间。
- `assistant_message` 和 `assistant_action`：刷新 Web/C5 共享会话。

SSE 断线时页面保留现有状态；重连后主动刷新站点快照和共享会话。5 秒 REST 轮询继续作为校准通道。

## 5. 助手与语音

前端同时保留两条助手链路：

- 页面 AI 对话通过 `/api/v1/assistant/turns` 创建任务，再使用 SSE 接收分阶段结果和建议动作。
- Web/C5 共享助手通过站点会话接口保存消息、待确认动作和执行状态。

涉及设备动作时，助手先生成待确认动作，用户确认后才进入站点命令或水枪流程。页面用 action ID 把助手动作状态与设备命令更新关联起来。

浏览器语音输入使用 Web Speech API，将识别文本写入输入框。后端同时提供 C5 使用的语音 HTTP/WebSocket 能力，但浏览器当前不依赖该后端语音接口。

## 6. 状态持久化

页面状态使用双层保存：

- 浏览器 `localStorage` 键为 `smartagribrain-dashboard-state`，用于后端不可用时快速恢复。
- `/api/v1/state/dashboard` 保存共享状态，后端返回非空状态时优先于本地值。

保存时先写本地，再尝试写后端。保存内容包括当前视图、目标范围、托管配置、助手布局与线程、天气城市、知识库选择等界面状态，不应包含 API Key、MQTT 密码或其他凭据。

## 7. 源码关系

- `src/App.vue`：当前应用状态、八个页面模板、主要交互流程和生命周期。
- `src/services/api.ts`：REST、SSE、上传和流式助手请求。
- `src/services/smartControl.ts`：页面侧智能托管计算与手动覆盖。
- `src/types.ts`：前端领域类型和接口数据结构。
- `src/components/CameraGrowthPanel.vue`：摄像头预览、抓帧和生长分析。
- `src/components/EChartPanel.vue`：ECharts 包装组件。
- `src/components/MarkdownContent.vue`：助手 Markdown 安全渲染。
- `src/components/StatusPill.vue`：状态标签。
- `src/utils/format.ts`：格式化和用户可读错误。
- `src/styles.css`：全局和各业务页面样式。

## 8. 开发约束

新增页面功能前先判断其状态属于页面本地状态、跨页面状态还是后端领域状态。设备事实和共享业务状态必须来自后端，不能只保存在组件中。

新增设备控制必须使用统一站点命令契约，并等待命令状态或 ACK；不得通过修改前端本地状态伪造执行成功。新增实时事件必须同时定义 SSE 事件名、负载类型、重连后的 REST 校准方式和幂等处理。

当前 `App.vue`、`styles.css` 和 `api.ts` 已超过适合继续集中开发的规模。后续拆分顺序见 [项目 README](../README.md)，但每次迁移都必须先有相应页面行为测试。

所有需要项目负责人确认的问题只写入仓库根目录 [问题与答复汇总](../../docs/open-questions.md)，本文件不建立第二份问题清单。

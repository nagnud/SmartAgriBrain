## 事实来源优先级

发生冲突时按以下顺序处理：

1. 已确认的用户答复和 `open-questions.md` 中的结论。
2. `smartagribrain-v1-standard.md` 中的正式目标契约。
3. 当前分支可直接核验的源代码行为。
4. 架构、工程说明和历史评审文档。

目标契约与当前代码不一致时，不得静默改写契约。应在实现状态中记录差异，并在后续代码任务中修复。

## 编写规则

- Markdown 使用标题、段落、列表和代码块，不使用表格。
- 所有未确认问题只写入 `open-questions.md`，其他文档引用 Q 编号。
- 临时标定、模拟数据和未完成联调必须显式说明，不能写成已经实测或验收。
- 文档中的“已实现”表示源码存在且可检查；“构建通过”表示编译链接通过；“真机通过”和“端到端通过”必须有相应测试记录后才能使用。

# ESP32 工程项目说明报告

最后同步日期：2026-07-22。

## 1. 项目定位

`esp32/` 是 SmartAgriBrain 的现场采集与执行节点。它连接农业传感器和现场执行器，通过 Wi-Fi 与 MQTT Broker 通信，将统一遥测交给云端服务，并把云端确认后的控制命令转换为 PWM 和舵机动作。

本工程不承担 Web 页面、数据库、语音识别、大模型推理或屏幕显示。ESP32-C5 负责语音与显示，普通 ESP32 负责实时采集与执行，两者通过统一后端间接协作。

## 2. 硬件范围

### 2.1 传感器

- 土壤湿度：GPIO34 ADC，当前干湿标定值为 3200 和 1400，仍需实物校准。
- BH1750：I2C 地址 `0x23`，上报 `illuminance_lux`。
- DS18B20：OneWire GPIO4，上报 `temperature_c`。
- JW01 CO2：串口驱动，上报 `co2_ppm`。

### 2.2 执行器

- GPIO14：补光灯，高电平有效，1 kHz、8 位 PWM，协议范围 0 至 90%。
- GPIO26：水泵，高电平有效，1 kHz、8 位 PWM，协议范围 0 至 100%。
- GPIO27：水平 SG90，50 Hz、16 位 PWM，软件范围 0 至 180 度。
- GPIO13：俯仰 SG90，50 Hz、16 位 PWM，软件范围 0 至 180 度。
- GPIO12：历史 WS2812 灯带，当前保留运行，但不响应补光灯 MQTT 命令。

水泵与水枪是同一物理水路。GPIO26 仅由水枪状态机调用，外部不得发送独立水泵命令，避免与云台目标和喷水安全顺序冲突。

两个 SG90 必须使用独立稳定 5 V 供电，并与 ESP32 共地。水泵和灯具必须经过匹配的 MOS 管、继电器或驱动板，不能由 GPIO 直接带载。

## 3. 工程结构

- `src/main.cpp`：硬件初始化、回调注册和主循环调度。
- `include/config.h`：本机 Wi-Fi、MQTT、证书和发送周期配置，已从 Git 忽略。
- `include/iot_contract.h`：设备 ID、固件版本、QoS、执行器范围和临时标定常量。
- `lib/mqtt/`：ESP-IDF MQTT 客户端、主题、消息解析、幂等缓存、ACK、状态、能力和遥测。
- `lib/wifi/`：Wi-Fi 连接和状态检查。
- `lib/PanTilt/`：二维 SG90 的 LEDC 配置、角度写入和当前角度保存。
- `lib/WaterGun/`：普通水泵与水枪共用的非阻塞控制状态机。
- `lib/BH1750/`、`lib/SoilSensor/`、`lib/ds18b20/`、`lib/JW01_CO2/`：四类传感器驱动。
- `lib/led/`：保留的 WS2812 模块。
- `lib/Pump/`、`lib/PidLed/`、`lib/PidPump/`、`lib/vofa/`：历史或辅助模块，不代表当前正式 MQTT 控制路径。
- `test/`：历史测试和独立验证代码，可能包含旧接口，不能替代主固件验收。

## 4. 构建与编辑器

工程使用 PlatformIO 和 Arduino 框架：

```ini
[env:esp32dev]
platform = espressif32
board = esp32dev
framework = arduino
monitor_speed = 115200
```

依赖包括 OneWire、DallasTemperature、FastLED 和 ArduinoJson。MQTT 使用 Arduino-ESP32 框架自带的 ESP-IDF MQTT 组件，不再使用 PubSubClient。

协议 ID `greenhouse_001_s3` 中的 `_s3` 不代表真实芯片。构建目标必须保持普通 `esp32dev`。

仓库根目录打开 VS Code 时，通过根 `.vscode/settings.json` 读取 `esp32/compile_commands.json`。依赖或编译参数变化后，在本目录执行：

```powershell
pio run -t compiledb
```

当前主固件已通过 PlatformIO 构建验证。该结论只证明源码可以编译链接，不等于真机与云端已经验收。

## 5. 启动顺序

1. 启动 115200 串口并输出真实芯片与协议 ID 提示。
2. 配置 GPIO14、GPIO26 的 PWM，并将补光灯和水泵写为关闭。
3. 将两个 SG90 初始化到 90 度。
4. 绑定 `WaterGunController` 与 GPIO26 唯一写入函数。
5. 初始化 BH1750、土壤湿度、DS18B20、JW01 CO2 和 WS2812。
6. 注册 MQTT 命令处理器、执行器快照和安全停止回调。
7. 连接 Wi-Fi。
8. 初始化 MQTT TLS、LWT、持久会话和收包队列。

执行器安全初始状态先于网络初始化。即使网络启动阶段出现异常，也不会留下默认开启的水泵。

## 6. 主循环

主循环固定按以下阶段推进：

1. 网络安全：Wi-Fi 断开时先请求停泵，再尝试重连；板载 LED 以 200 ms 周期闪烁提示断网。
2. MQTT：处理连接事件、完整消息队列、JSON 校验、幂等判断和命令分发。
3. 水枪状态机：推进 800 ms 舵机稳定等待、本地定时截止和动态 3 秒超时。
4. 传感器：推进土壤、CO2、温度和 WS2812 模块更新。
5. 遥测：到达 `SEND_INTERVAL_MS` 后发布传感器与执行器统一快照。

MQTT 回调不执行舵机移动或阻塞等待。这样可以避免网络任务被 800 ms 稳定时间占用，也保证水枪安全逻辑集中在 Arduino 主循环中。

## 7. MQTT 实现

### 7.1 连接

- MQTT 版本：3.1.1。
- 传输：TLS，当前配置端口 8883，并使用 CA 证书校验。
- Client ID：`sab-dev-greenhouse_001_s3`。
- 会话：持久会话。
- keepalive：30 秒。
- 自动重连：5 秒。
- 命令队列：网络任务把完整 JSON 放入 FreeRTOS 队列，主循环消费。

### 7.2 主题

主题前缀是 `smartagribrain/v1/devices/greenhouse_001_s3`。设备订阅 `command`，发布 `command_ack`、`telemetry`、`status` 和 `capabilities`。所有主题及 LWT 使用 QoS 1；状态和能力使用 retain。

### 7.3 命令

原子 `set` 命令只支持 `grow_light`。目标喷水使用 `target_position`，在一条消息中携带地面距离、方向角、静态/动态模式、是否喷水、水泵百分比、会话序号和定时参数。

协议版本和设备身份由精确 `command` Topic 确定。设备校验命令 ID、绝对失效时间和业务字段；已过期或超过未来 300 秒的命令不会操作 GPIO。相同命令 ID 和相同内容只重发第一次 ACK；同 ID 不同内容按冲突拒绝。

### 7.4 上行消息

- `capabilities`：声明四类传感器、补光灯和水枪能力。
- `status`：声明在线状态和原因，异常断开由 LWT 发送离线状态。
- `telemetry`：包含遥测去重 ID、四类传感器、补光灯 PWM、云台角度、水枪状态和 RSSI。
- `command_ack`：包含最终状态、实际应用值、错误码和 `feedback_verified=false`。

SG90 和水路都没有反馈传感器，所以 ACK 的 `executed` 只表示控制输出已经写入且状态机无错误。

MQTT JSON 不重复 Topic 已提供的版本和设备 ID。站点、命令来源、原因和创建时间保存在后端数据库；ACK 不回显后端已经保存的原命令。

## 8. 水枪控制

### 8.1 状态机顺序

1. 接受已经通过 MQTT 校验的命令。
2. 处理有效停止请求或目标变化，先关闭水泵。
3. 把临时目标坐标映射为水平和俯仰角。
4. 写入舵机目标并进入等待状态。
5. 800 ms 后建立定时或动态保护。
6. 写入水泵 PWM。
7. 发布异步最终 ACK。

### 8.2 安全规则

- 静态定时模式同时使用 Epoch 截止时间和 `millis()` 单调截止。
- 动态模式要求同一 `session_id` 下 `sequence` 严格递增。
- 动态模式 3 秒没有合法更新时停泵。
- 新目标、网络断开和已认证非法水枪命令都会触发统一停泵。
- 水泵 1 至 39% 暂时提升到 40%，ACK 返回实际应用值。

### 8.3 临时标定

方向角 -90 至 90 度继续线性映射到水平舵机 0 至 180 度。垂直舵机受实体机构限制，只允许 5 至 60 度：5 度时水枪平行向前，60 度时水枪竖直向上。目标距离 300 至 1200 mm 单段线性映射到 60 至 5 度，其中 300 mm 对应 60 度，1200 mm 对应 5 度。垂直机械端点已经确认，但该距离关系尚未结合实际水压、喷嘴和落点完成标定。

## 9. 当前缺口与验收

### 9.1 已知实现差异

- 当前 `SEND_INTERVAL_MS=5000`，即 5 秒，已与正式遥测周期一致。
- 状态和能力是 retained 快照，不使用消息级去重 ID；遥测保留 UUID `message_id`。
- 遥测包含 `quality`；当前裸板阶段允许未接传感器产生 0、-127 或浮空 ADC 值，这些值不能作为真机验收结果。
- ACK 缓存固定为 50 条，但没有独立的 10 分钟过期策略。
- 临时坐标、水泵启动值和机械安全范围尚未实测。
- 前端/FastAPI 只使用真实 REST、EMQX MQTT 和设备 ACK；实体设备是否在线仍需现场验收。
- Web heartbeat 尚未转换为设备可见的 MQTT 保活，C5 也尚未获取最终 `command_ack` 状态。

### 9.2 真机验收

1. 验证四类传感器读数、单位、无效值和更新时间。
2. 验证 GPIO14、GPIO26 的驱动板、电平有效性和 PWM 范围。
3. 验证 GPIO27、GPIO13 的方向、机械限位、供电和共地。
4. 验证 TLS、持久会话、QoS 1 重发和 Broker 离线队列。
5. 验证重复、过期、乱序、断网、定时和模拟命令不会造成危险输出。
6. 验证后端保存 ACK，并且 Web/C5 只在设备 ACK 后显示控制已应用。

## 10. 总结

当前 ESP32 工程已经从旧测试主题和简单回调控制迁移为正式 v1 MQTT、QoS 1、统一命令模型和非阻塞水枪状态机。代码层已经具备采集、上报和执行框架；剩余工作的重点是严格契约补齐、真实硬件标定、Broker 策略确认以及端到端联调，而不是继续增加未经验证的新控制字段。
